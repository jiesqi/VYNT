VYNT Security

Reporting a Security Issue

If you discover a security vulnerability affecting VYNT, please report it privately to VYNT Technologies.

Do not publicly disclose the vulnerability before it has been reviewed and addressed.

When reporting an issue, please include:

* A description of the vulnerability
* Steps to reproduce the issue
* The potential security impact
* Relevant screenshots, logs, or proof of concept when appropriate
* Any suggested mitigation

What Not to Include

Never include the following in a public GitHub issue, pull request, or discussion:

* API keys
* Passwords
* OAuth credentials
* Stripe secrets
* Database credentials
* License keys
* Authentication tokens
* Personal user data
* Private creator data

Security Principles

VYNT is designed with security as a core part of the platform.

Key security principles include:

* Server-side authentication and authorization
* Server-side subscription verification
* Secure API key handling
* Hashed license keys
* Device and session controls
* API rate limiting
* Environment-based secret management
* Audit logging
* Authorized third-party API integrations
* Protection of creator and account data
* HTTPS for production communications

Third-Party Integrations

VYNT integrations are designed to use authorized APIs and approved authentication methods.

VYNT does not intentionally rely on:

* Credential harvesting
* Unauthorized access
* Security bypasses
* Circumventing platform protections
* Exposing private API credentials

Responsible Disclosure

VYNT Technologies asks security researchers and users to provide reasonable time to investigate and address reported vulnerabilities before public disclosure.

We appreciate responsible security research that helps improve VYNT.

Scope

This repository primarily contains public documentation and product information.

The proprietary VYNT application source code and production infrastructure are not contained in this repository.
